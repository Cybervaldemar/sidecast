# Разработка

Новая версия находится в корне репозитория. `stable/` — неизменённая копия прежней версии Node.js; изменения туда не переносим.

Нужны Node.js 20.11+ и Go версии из `go.mod` или новее.

```sh
npm ci
npm run build
npm run dev:server
# В другом терминале:
npm run dev
```

Студия разработки: http://localhost:5173. Vite направляет `/api` на Go-сервер :8080. При разработке оба устройства должны использовать один origin; для проверки зрителя удобнее production-сборка на :8080.

```sh
npm run check
npm test
npm run build:app
npx playwright install chromium
npm run test:e2e
npm run build:all
```

Браузерный тест запускает свой сервер на 127.0.0.1:18080, отдельный браузер и временную базу каналов. Только в этом браузере захват подменяется движущимся canvas и звуковым генератором. Проверяются декодированные кадры, ненулевая энергия полученного звука, повторные эфиры, перезапуск сервера и мобильная вёрстка. На Windows используется установленный Chrome, если он найден; `SIDECAST_CHROME` позволяет выбрать другой исполняемый файл. Эти тесты не проверяют реальный захват игры, системного звука и производительность целевого сервера.

Go-тесты проверяют хранение прав, гонку регистрации, HTTP-права и передачу RTP через настоящий WebRTC. В CI дополнительно включён детектор гонок Go.

Нативная сборка Studio с FFmpeg/WASAPI временно отключена; её исходники и тестовые заготовки сохранены для дальнейшей работы. Доступные сборки используют браузерный захват.

Проверка реального значка трея в интерактивной Windows-сессии: `SIDECAST_TEST_TRAY=1` и `node scripts/go.mjs test -count=1 -v ./internal/desktop`. Тест регистрирует значок, проверяет запрос открытия `/studio`, отправляет команду «Выход» и проверяет удаление окна; реальный браузер заменён тестовым обработчиком. Браузерные E2E-тесты используют `--no-tray` и дополнительно проверяют полное завершение процесса кнопкой студии во время эфира, остановку захвата и отсутствие кнопки у зрителя. Серверные тесты проверяют запрет удалённого выключения, чужого origin и неверного или устаревшего ключа управления.

Иконка Windows создаётся из `web/public/favicon.svg`: `npm run icons:windows` обновляет `internal/desktop/app.ico` и `cmd/sidecast/rsrc_windows_amd64.syso`. Для этой команды нужны Chromium Playwright или Chrome (`SIDECAST_CHROME`) и доступ к Go-модулям для закреплённого `go-winres@v0.3.3`. Результаты генерации входят в репозиторий; обычная сборка автоматически встраивает ресурсы Windows, не запуская генератор. Один ICO используется для ресурсов EXE и трея.

Сборки лежат в `build/windows-amd64/` и `build/linux-amd64/`. `npm run build:app` создаёт сборку текущей поддерживаемой платформы, `npm run build:all` — обе. ARM и варианты для роутеров исключены. Обе команды очищают предыдущие артефакты, включая старые ARM/MIPS; данные каналов должны храниться вне `build/`.

Компоненты UI — в `web/src/components`, страницы — в `pages`, жизненный цикл соединений — в `hooks`, HTTP и WebRTC — в `lib`. Не добавляйте обработку сетевых соединений непосредственно в визуальные компоненты. Серверные пакеты: `channels` (хранение), `media` (WebRTC), `httpapi` (маршруты и права).

Форматирование фронтенда: `npm run format` применяет Prettier, `npm run format:check` проверяет стиль без изменения файлов. Проверка также выполняется в CI. Используем два пробела для отступов, отдельную строку для каждого объявления переменной и пустые строки между логическими блоками, в том числе перед `return`, если перед ним есть другие инструкции. Последние два соглашения соблюдаем при редактировании: Prettier сохраняет пустые строки, но не добавляет их сам.

Перед PR приложите описание поведения и результаты проверок. Не включайте ключи владельцев, `data/`, сертификаты, тестовые результаты и собранные бинарные файлы.
